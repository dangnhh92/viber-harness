# TRUTH

What is true about this project right now. Nothing else.

Every claim is one paragraph and carries an anchor, so a change to the code can be traced
to the claim it invalidates. A blank line ends a claim:

- `{% ref file="src/config.ts" symbol="MAX_ITEMS" %}` for something the code decides.
- `{% ref record="R-042" %}` for something a person decided.

`viber truth check` resolves every anchor and exits non-zero when one is broken or missing.

**A line belongs here only if both hold.** It can be checked against a file in this repo,
right now, without asking anyone. And it is still true when nobody is here to be asked.

That excludes four things, each with its own home:

| Not truth | Because | Goes to |
|---|---|---|
| "not sure whether it was submitted" | the agent's own ignorance, not a fact about the project | ask the owner |
| "currently in review" | state outside the repo, goes wrong with nobody noticing | a dated record |
| "rejected for a missing privacy string" | history | a record |
| "about to bump to 1.3" | intent | a record |

A dated record never goes stale, because it does not claim to describe the present. This
file does, which is why it is restricted to what the repo can prove about itself.

Delete the sections below that do not apply and write the ones that do.
